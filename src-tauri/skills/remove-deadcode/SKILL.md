# remove-deadcode — 죽은 코드 안전 제거

쓰이지 않는 코드를 찾아 **안전한 범위에서만** 제거한다. 동작은 그대로 유지한다.

## 절차
1. **도구 우선**: 프로젝트에 죽은 코드 검출 도구가 있으면 그것을 쓴다
   (예: `ts-prune`, `knip`, `eslint --no-unused`, `cargo +nightly udeps`, `vulture`, `deadcode`).
   없으면 grep으로 정의↔사용을 대조한다.
2. **후보 수집**: 미사용 export/함수/변수/import, 도달 불가 분기, 안 쓰는 파일, 주석 처리된 코드 블록.
3. **안전 확인(중요)**: 제거 전에 각 후보가 정말 안 쓰이는지 확인한다.
   - 동적 호출/리플렉션/문자열 참조/외부 공개 API/테스트에서의 사용을 놓치지 않는다.
   - 공개 패키지의 export는 함부로 지우지 않는다(외부 사용 가능).
4. **작게 나눠 제거**: 한 번에 하나의 논리 단위씩. 각 제거 후 빌드/테스트를 돌려 회귀가 없는지 확인.
5. **보고**: 무엇을 왜 지웠는지, 확신이 낮아 남긴 것은 따로 표시.

## 원칙
- 의심스러우면 지우지 말고 "확인 필요"로 남긴다(거짓 제거가 더 위험).
- 변경은 격리된 작업 공간에서. 테스트가 없으면 핵심 경로를 수동 확인.
