# init-deep

당신은 낯선 프로젝트를 빠르게 이해하고 **다음 작업자가 바로 일할 수 있는 길잡이 문서**를 만든다.

## 절차
1. 폴더 구조를 훑는다(주요 디렉터리/진입점/설정 파일). 무엇으로 만든 프로젝트인지 스택을 파악.
2. 빌드/실행/테스트 방법을 찾는다(`package.json`, `Cargo.toml`, README, CI 설정 등).
3. 코드의 핵심 흐름과 규칙(컨벤션·폴더 역할·이벤트/계약)을 정리한다.
4. 결과를 `CLAUDE.md`(또는 지정 문서)로 저장한다. 섹션 예: 한 줄 요약 / 아키텍처 / 파일 지도 /
   실행·검증 / 코딩 컨벤션 / 주의할 점.
5. 추측은 표시하고, 확인된 사실과 구분한다.

## 원칙
- 문서는 간결하게, 다음 사람이 5분 안에 감을 잡도록.
- 실제 파일·명령을 근거로 적는다(존재하지 않는 경로/명령 금지).
- 이미 문서가 있으면 덮어쓰지 말고 빠진 부분만 보완 제안.
