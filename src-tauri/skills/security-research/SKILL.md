# security-research — 방어적 보안 점검

코드베이스를 방어 관점에서 점검해 위험을 찾아 **보고만** 한다(파일 미수정). 악용/공격 도구는 만들지 않는다.

## 0단계 — 빠른 스캔 (스크립트)
가능하면 동봉 스크립트로 흔한 비밀 노출을 먼저 훑는다(있는 OS 것 사용):
- macOS/Linux: `bash scripts/scan-secrets.sh <폴더>`
- Windows: `powershell -File scripts/scan-secrets.ps1 <폴더>`
스크립트 결과는 출발점일 뿐 — 반드시 사람이 맥락을 확인한다(거짓 양성 제거).

## 1단계 — 체계적 점검
다음을 grep/읽기로 확인한다:
- **비밀 노출**: 하드코딩 API 키/토큰/비밀번호, 커밋된 `.env`, 로그의 민감정보.
- **인젝션**: SQL/명령/경로 인젝션, 신뢰 못 할 입력의 직접 사용, 위험한 역직렬화.
- **인증/인가**: 누락된 권한 검사, 약한 세션/토큰, 안전하지 않은 비교.
- **위험 함수**: `eval`/`exec`, 사용자 입력을 결합한 셸 호출, 약한 난수/해시.
- **전송/저장**: 평문 전송, 검증 없는 TLS, 민감정보 평문 저장.

## 2단계 — 분류와 보고
- 심각도: **[치명] / [높음] / [중간] / [낮음]**.
- 각 발견: `파일:줄` → 무엇이 왜 위험 → 권장 수정(예시 코드) → 근거.
- 거짓 양성은 표시하고 제외. 마지막에 요약(치명/높음 개수)과 다음 조치 제안.

## 원칙
- 발견·설명·방어 권고만. 실제 악용 코드는 쓰지 않는다.
- 추측과 확인을 구분한다. 수정은 사용자 승인 후 별도 작업으로.
