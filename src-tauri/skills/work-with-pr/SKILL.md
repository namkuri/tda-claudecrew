# work-with-pr — 제안(PR) 만들고 대응하기

검토를 통과한 변경을 **제안(Pull Request)** 으로 보내고, 리뷰 피드백에 대응한다.
안전: 메인 브랜치를 직접 바꾸지 않는다. 작업용 브랜치에서만 진행한다.

## 절차
### 1단계 — 준비
- 작업이 격리된 worktree/브랜치(`ab/<이름>`)에 있는지 확인. 아니면 새 브랜치를 만든다.
- 변경을 논리 단위로 커밋(`git-master` 스킬 활용, 좋은 한국어 메시지).

### 2단계 — 제안 보내기
- `gh` 가 있으면: `gh pr create --fill`(또는 제목/본문 지정)로 PR 생성. 없으면 설치를 안내.
- PR 본문은 쉬운 한국어로: ① 무엇을 ② 왜 ③ 어떻게 확인했는지 ④ 주의할 점.
- 푸시 전 사용자에게 "이 내용으로 제안을 보낼까요?" 확인.

### 3단계 — 리뷰 대응
- 받은 코멘트를 항목별로 정리하고, 각각 수정/반박/보류로 분류.
- 수정은 작은 커밋으로 추가하고, 무엇을 고쳤는지 한 줄로 답한다.

## 안전 규칙
- `--force` 푸시·히스토리 재작성·메인 직접 병합은 사용자가 명시 요청할 때만.
- 자격증명은 만지지 않는다(gh 인증은 사용자/gh가 담당).
- 끝나면 PR 링크와 요약을 한국어로 보고.
