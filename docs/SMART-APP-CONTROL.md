# Smart App Control / SmartScreen 차단 안내

ClaudeCrew는 **코드 서명 인증서가 없는 무료 배포 앱**입니다. Windows의 보안 기능이
설치·실행을 막을 수 있는데, 이는 악성코드라서가 아니라 **"아직 평판이 쌓이지 않은
서명 안 된 앱"** 이기 때문입니다. 새 버전을 낼 때마다 실행 파일 해시가 바뀌어
평판이 0으로 초기화되므로, 매 릴리스 초기에 더 자주 차단됩니다.

## 두 기능의 차이

| 기능 | 동작 | 우회 |
|------|------|------|
| **SmartScreen** | "Windows의 PC 보호" 파란 창 | **추가 정보 → 실행**으로 통과 가능 |
| **Smart App Control(SAC)** | 더 엄격 — "실행" 버튼 없이 차단 | 앱을 **서명**하거나 SAC를 끄거나 허용해야 함 |

> SAC는 Windows 11의 새 보안 기능으로, **서명되지 않은 앱은 "실행 안 함"으로 즉시 차단**합니다.
> SmartScreen과 달리 한 번에 허용하는 버튼이 없습니다.

## 사용자 입장에서 지금 쓰는 방법

### 방법 A — 포터블 exe 사용(권장, 무설치)
릴리스의 `claudecrew-windows-portable` 아티팩트에서 `claudecrew.exe`를 받아 실행하세요.
설치 관리자(NSIS/MSI)를 거치지 않아 차단을 피하기 쉽습니다. 그래도 SAC가 막으면 방법 B/C로.

### 방법 B — 이 앱만 허용
1. SmartScreen 창이라면: **추가 정보 → 실행**.
2. 파일 속성: `claudecrew.exe` 우클릭 → **속성** → 하단 **차단 해제(Unblock)** 체크 → 확인.

### 방법 C — Smart App Control 평가/끄기
- **설정 → 개인 정보 및 보안 → Windows 보안 → 앱 및 브라우저 컨트롤 → 스마트 앱 컨트롤**
- SAC는 한번 끄면 **재설치(클린 설치) 전엔 다시 켤 수 없으니** 신중히 결정하세요.
- 가능하면 끄지 말고, 아래 "근본 해결(서명)"을 통해 서명된 빌드를 받는 걸 권장합니다.

## 근본 해결 — 코드 서명

SAC/SmartScreen이 **신뢰**하려면 앱이 코드 서명 인증서로 서명되어야 합니다.

| 옵션 | 비용/특징 | 신뢰 획득 |
|------|-----------|-----------|
| **Azure Trusted Signing** | 월 ~$9.99, 개인/소규모 사업자 가능 | Microsoft가 신뢰하는 체인 — SAC에 효과적 |
| **EV 코드 서명 인증서** | 연 $250~400+ | 서명 즉시 SmartScreen 평판(즉시 신뢰) |
| **OV/표준 인증서** | 연 $100~200 | 서명되지만 평판은 시간이 지나며 축적 |
| **Microsoft에 분석 제출**(무료) | 무서명 그대로 | https://www.microsoft.com/wdsi/filesubmission 에 제출하면 오탐 완화 |

> **안전 원칙**: 인증서·자격증명은 **사용자 소유물**입니다. ClaudeCrew는 인증서를
> 만들거나 보관하지 않습니다. 사용자가 인증서를 발급받아 GitHub Secrets에 넣으면,
> CI가 그 인증서로 서명하도록 구성할 수 있습니다(아래).

## CI 서명 연결(인증서가 있을 때)

GitHub 저장소 **Settings → Secrets and variables → Actions** 에 다음을 추가하면
릴리스 빌드가 자동 서명되도록 워크플로를 확장할 수 있습니다(요청 시 구성):

- `WIN_CERT_BASE64` — `.pfx` 인증서를 base64로 인코딩한 값
- `WIN_CERT_PASSWORD` — 인증서 비밀번호

또는 **Azure Trusted Signing** 사용 시 해당 엔드포인트/계정 정보를 Secrets로 추가합니다.
