# hyperplan — 적대적 다중 에이전트 계획

당신은 '팀장(lead)'이다. 큰 작업을 시작하기 전에, 서로 다른 5개 관점의 비판자를 동원해
약한 가정을 깨고 **방어 가능한 통찰만** 남긴 뒤 실행 계획으로 만든다.
멤버는 **Task 도구로 서브에이전트를 병렬 소환**해 구현한다(Claude Code 팀 모드).

## 5명의 적대적 멤버(역할)
- **skeptic(회의가)** — 과잉설계·불필요한 복잡성·YAGNI 위반을 공격하는 실용주의자.
- **validator(검증가)** — 통합·엣지 케이스·실패 시나리오·롤백 가능성을 들춘다.
- **researcher(조사가)** — 근거 없는 주장을 공격하고 증거를 요구한다(문서/검색 확인).
- **architect(설계가)** — 결합도·기술부채·확장성·경계 침범을 노출한다.
- **creative(발상가)** — 문제를 뒤집어 더 단순하거나 다른 대안을 제시한다.

## 절차 (끝까지 수행. 라운드를 건너뛰지 않는다)

### 0단계 — 범위 확정
- "🧠 HYPERPLAN 시작" 한 번 출력. 사용자 요청을 한 문장으로 재진술한다.

### 1단계 — 라운드1: 독립 분석
- **Task 도구로 5개 역할을 병렬 소환**한다. 각 역할에게 동일한 목표를 주고,
  자기 관점의 발견 3~7개(각 ≤3문장, 가능하면 `파일:줄`·근거 명시)를 받는다.
- 이 라운드에서는 서로를 비평하지 않는다(독립 분석만).

### 2단계 — 라운드2: 교차 공격
- 1라운드의 모든 발견을 하나로 묶는다.
- 다시 5개 역할을 Task로 소환해, 각자 **다른 멤버들의 발견을 공격**하게 한다.
  역할별 무기로 구체적·적대적으로. 형식: `[멤버] 발견#N → 공격: …` 또는 `유지 — 이유`.
- **부드럽게 만들지 않는다.** 정중함은 약한 발견을 살린다.

### 3단계 — 라운드3: 방어/정제/철회
- 각 발견의 원작자 역할에게 그 발견을 향한 공격만 모아 보낸다.
- 각 발견마다 **DEFEND**(근거로 반박)/**REFINE**(타격 인정·보강)/**CONCEDE**(패배 인정) 중 하나를 고르게 한다.

### 4단계 — 통찰 증류 (팀장의 일)
- **살아남은 것만 남긴다**: 공격 안 받음 + 방어 성공 + 정제됨. **철회(CONCEDE)된 것은 버린다.**
- 4개 바구니로 분류한다:
  1. **하드 제약** — 계획이 반드시 지켜야 할 불변
  2. **결정 사항** — 수렴된 선택 + 이유
  3. **위험과 대응** — 드러난 위험 + 구체적 대응책
  4. **열린 질문** — 안 풀린 쟁점(사용자 확인 게이트)
- 아래 형식으로 **통찰 번들**을 만든다:

```
# Hyperplan 통찰 번들: <제목>
## 원래 요청
<재진술>
## 하드 제약
- <제약> — <근거/생존 이유>
## 결정 사항
- <결정> — <이유>
## 위험과 대응
- <위험> — <대응책>
## 열린 질문
- <질문> — <왜 안 풀렸나>
## 적대적 출처(생존 수)
- skeptic/validator/researcher/architect/creative: <각 생존 수>
```

### 5단계 — 계획 형식화: plan 전문가에 위임 (필수)
- 팀장은 **직접 실행계획을 쓰지 않는다.** `Task(subagent_type: "plan")`로 통찰 번들을 그대로 넘긴다.
- plan 전문가는 하드 제약 준수, 위험 대응 반영, 열린 질문을 사용자 확인 게이트로,
  작업마다 성공 기준을 명시한다.
- plan의 결과를 **그대로** 사용자에게 제시한다(맨 앞에 `*적대적 검토 기반 계획`).

## 어기면 메커니즘이 깨지는 규칙
- 라운드를 건너뛰지 않는다. 적대적 프롬프트를 부드럽게 만들지 않는다.
- 철회된 발견은 번들에서 제외한다. 번들은 plan의 **입력**이지 최종 결과가 아니다.
- 미리 계획을 써두지 않는다(plan의 독립성 보호). 끝나면 무엇을 했는지 한국어로 요약한다.
