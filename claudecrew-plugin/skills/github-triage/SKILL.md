# github-triage — 이슈/PR 분류 (읽기 전용)

GitHub의 이슈/PR을 모아 분석하고 **우선순위를 제안**한다. 저장소를 변경하지 않는다(읽기 전용).

## 0단계 — 목록 수집 (스크립트)
`gh` CLI가 있으면 동봉 스크립트로 목록을 빠르게 가져온다(없으면 사람이 붙여넣어도 됨):
- macOS/Linux: `bash scripts/gh-list.sh [owner/repo]`
- Windows: `powershell -File scripts/gh-list.ps1 [owner/repo]`
`gh`가 없으면 설치를 안내하고, 사용자가 준 목록으로 진행한다.

## 1단계 — 분류
각 항목을 다음으로 태깅한다:
- **유형**: 버그 / 기능요청 / 질문 / 문서 / 잡일(chore)
- **심각도**: 막힘(blocker) / 높음 / 보통 / 낮음
- **상태**: 재현됨 / 정보부족 / 중복 / 바로 가능(good-first)

## 2단계 — 우선순위 제안
- "지금 처리" / "곧" / "나중에" 3구간으로 정렬. 각 항목에 한 줄 이유.
- 중복·정보부족 항목은 따로 묶어 "응답 템플릿"(쉬운 한국어)을 제안.

## 3단계 — 보고
- 표로 요약(번호·제목·유형·심각도·추천 조치).
- 바로 처리 가능한 것(good-first) 3개를 콕 집어 추천.

## 원칙
- 읽기 전용. 라벨/코멘트 등 실제 변경은 사용자 승인 후 별도 작업으로.
- 추측과 확인을 구분한다.
