# pre-publish-review — 배포 전 다중 관점 검토 게이트

변경을 내보내기 전에 **여러 전문가 관점으로 병렬 검토**해, 통과해야 내보낼 수 있게 하는 품질 게이트.

## 절차
### 1단계 — 변경 파악
- `git diff`(작업 worktree의 cached 포함)로 이번에 무엇이 바뀌는지 정확히 모은다.

### 2단계 — 병렬 검토 (Task 도구로 전문가 동시 소환)
다음 관점을 **각각 별도 Task로** 동시에 돌린다(겹치지 않게 역할 분리):
- **정확성**(debugger): 버그·엣지 케이스·회귀 가능성.
- **보안**(security): 비밀 노출·인젝션·권한.
- **품질**(code-reviewer): 가독성·중복·에러 처리·명명.
- **테스트**(test-writer 관점): 검증 누락·깨지기 쉬운 테스트.
- **문서**(doc-writer 관점): 사용자 영향이 설명됐는지.

### 3단계 — 집계 및 판정
- 발견을 심각도로 모은다: **[막음(blocker)] / [권장] / [선택]**.
- **[막음]이 하나라도 있으면 "내보내기 보류"** 로 판정하고 무엇을 고쳐야 하는지 제시.
- 막음이 없으면 "통과 — 내보내도 좋음"으로 판정하고 권장/선택 항목을 요약.

## 원칙
- 판정은 보수적으로. 의심되면 [막음]보다 [권장]으로 두되 근거를 명확히.
- 각 발견에 `파일:줄`과 한 줄 이유. 끝에 한국어 요약(막음 N / 권장 N / 선택 N).
